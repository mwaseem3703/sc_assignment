
Act as a Technical Project Manager. I am building a Campus Event Management System for COMSATS University Vehari Campus. Please read the following raw stakeholder brief and generate two things:

1. A Work-Breakdown Structure (WBS) dividing the project into 4-5 major technical categories.
2. A list of Agile User Stories broken down by feature, prioritized using the MoSCoW method (Must, Should, Could, Won't).

Raw Stakeholder Brief:
"We need a system for campus events. Students need to be able to log in with their university accounts and see a list of upcoming events. They should be able to click on an event to see the full details, time, and location, and search for specific events if there are a lot of them.

Students have to be able to register for the events so we know who is coming, but make sure they can't register twice by accident. It would be nice if they could cancel if they change their minds. The system must automatically send them a reminder before the event happens, ideally with the time and location. If a reminder fails to send, the system should probably try again.

Finally, the university admins need a way to log in and actually create these events, publish them, or delete them if they are canceled. The system needs to make sure the admin fills out all the required fields before it lets them hit publish."
